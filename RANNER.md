# Свой раннер: как сделать всё через GitHub

Задача была «чтобы всё происходило в облаке, а не на компьютере». Полностью
в облаке не выйдет, и это проверено запуском, а не предположением.

## Что показала проба

Воркфлоу «Проба · пустит ли YouTube раннер», запуск 20.09.2026 на обычном
раннере GitHub:

```
ERROR: [youtube] Sign in to confirm you're not a bot.
```

И на метаданных, и на скачивании. Раннеры GitHub сидят на датацентровых
адресах Azure, YouTube их заворачивает.

**При этом радар работает.** Он читает обычную HTML-страницу канала, а её
отдают всем. Блокируется не сайт целиком, а проигрыватель — то, откуда
берётся само видео и субтитры.

Итого: **числа из облака берутся, видео — нет.**

## Три варианта и почему выбран третий

**Куки в секрет репозитория.** Выгрузить из браузера cookies.txt, положить
в секреты, передавать `--cookies`. Работает, но: ваш аккаунт Google начинает
ходить с датацентрового адреса — это ровно тот признак, по которому аккаунты
и блокируют; куки живут недели и требуют обновления руками. Я против.

**Платный жилой прокси.** Работает, стоит денег, ломается вместе с
провайдером. Городить ради пяти роликов в неделю незачем.

**Свой раннер — выбран.** Компьютер регистрируется в репозитории как
исполнитель. Расписание, кнопка запуска, логи, коммиты — всё в GitHub, как
вы и хотели. Компьютер нужен только включённым; в терминал больше не лезете.

## Как поставить, один раз

1. GitHub → репозиторий `lanskoy-motion` → **Settings** → **Actions** →
   **Runners** → **New self-hosted runner** → **Windows**.
2. На странице будут четыре команды: скачать, распаковать, `config.cmd` с
   токеном и `run.cmd`. Выполнить их в PowerShell как есть.
3. Когда спросит **labels** — ничего не добавлять, хватит стандартных.
4. Чтобы раннер поднимался сам при включении компьютера, вместо `run.cmd`:
   ```
   .\svc.cmd install
   .\svc.cmd start
   ```
   Так он живёт службой Windows и не требует открытого окна.

Нужен `ffmpeg` в PATH — его воркфлоу проверяет первым шагом и падает с
понятной ошибкой, если нет.

## Как этим пользоваться

**Само:** по понедельникам в 09:40 по Москве, после ночного радара. Берёт
пять самых горячих роликов, измеряет, коммитит кадры и числа.

**Руками:** Actions → «Снимок чужих роликов» → Run workflow. Там два поля:
сколько роликов взять и ссылка на конкретный ролик, если нужен именно он.

Если компьютер был выключен — запуск по расписанию просто не состоится,
очередь не копится. Следующий понедельник или кнопка.

## Чего нельзя забыть про безопасность

Репозиторий публичный, а свой раннер — это ваш компьютер. Чужой pull request
на публичный репозиторий в принципе может попытаться выполнить на нём код.
Защита:

- в **Settings → Actions → General → Fork pull request workflows** должно
  стоять требование одобрения для сторонних (по умолчанию так и есть);
- наш воркфлоу запускается только по расписанию и по кнопке, на события
  pull request он не реагирует вообще.

Если однажды репозиторий станет приватным — вопрос снимется сам.
