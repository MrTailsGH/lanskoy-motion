# Свой раннер: подробная установка

Цель: управление остаётся в GitHub — расписание, кнопка, логи, коммиты, — а
скачивание роликов выполняется на вашем компьютере. В терминал вы после
установки не заходите.

## Почему нельзя просто в облаке

Проба 20.09.2026 на обычном раннере GitHub (воркфлоу «Проба · пустит ли
YouTube раннер»):

```
ERROR: [youtube] Sign in to confirm you're not a bot.
```

И на метаданных, и на скачивании. Раннеры GitHub сидят на датацентровых
адресах, YouTube их заворачивает. Радар при этом работает: он читает обычную
HTML-страницу канала, а её отдают всем. Блокируется проигрыватель — то,
откуда берётся видео и субтитры.

Куки из браузера в секретах репозитория проблему решают, но ценой аккаунта:
он начинает ходить с датацентрового адреса, а это ровно тот признак, по
которому аккаунты блокируют. Не стоит того.

---

## Шаг 0. Что должно быть на компьютере

Проверьте четыре вещи. Откройте PowerShell и выполните по очереди:

```powershell
git --version
python --version
ffmpeg -version
bash --version
```

Что делать, если чего-то нет:

| Чего нет | Команда | Примечание |
|---|---|---|
| `git` и `bash` | `winget install Git.Git` | `bash` приходит вместе с Git для Windows, отдельно ставить не надо |
| `python` | `winget install Python.Python.3.12` | при установке с сайта python.org **обязательно** галочка «Add python.exe to PATH» |
| `ffmpeg` | `winget install Gyan.FFmpeg` | |

**После любой установки закройте PowerShell и откройте заново** — иначе он не
увидит изменившийся PATH.

Репозиторий должен быть склонирован локально. Если ещё нет:

```powershell
cd "C:\Lanskoy Claude"
git clone https://github.com/MrTailsGH/lanskoy-motion.git
```

## Шаг 1. Получить страницу установки в GitHub

1. Откройте `https://github.com/MrTailsGH/lanskoy-motion`
2. **Settings** (шестерёнка в верхней строке репозитория, не в профиле)
3. Слева: **Actions** → **Runners**
4. Зелёная кнопка **New self-hosted runner**
5. **Runner image: Windows**, архитектура **x64**

GitHub покажет готовые команды с вашим личным токеном. Их и выполняем —
ниже объяснено, что делает каждая.

**Токен на странице живёт примерно час.** Если не успели — обновите страницу,
он выдастся новый.

---

## Шаг 2. Выполнить команды

Откройте PowerShell **от своего имени** (не от администратора — это
понадобится только на шаге 4).

**2.1. Папка и скачивание.** Команды вида:

```powershell
mkdir C:\actions-runner; cd C:\actions-runner
Invoke-WebRequest -Uri https://github.com/actions/runner/releases/download/v2.XXX.X/actions-runner-win-x64-2.XXX.X.zip -OutFile actions-runner.zip
```

Номер версии подставит сам GitHub — копируйте с его страницы, не отсюда.

**2.2. Распаковка:**

```powershell
Add-Type -AssemblyName System.IO.Compression.FileSystem
[System.IO.Compression.ZipFile]::ExtractToDirectory("$PWD/actions-runner.zip", "$PWD")
```

**2.3. Привязка к репозиторию** — вот эта команда содержит ваш токен:

```powershell
.\config.cmd --url https://github.com/MrTailsGH/lanskoy-motion --token ВАШ_ТОКЕН
```

Она задаст четыре вопроса. Ответы:

| Вопрос | Что отвечать |
|---|---|
| `Enter the name of the runner group` | просто Enter (группа Default) |
| `Enter the name of this runner` | Enter (имя компьютера) или своё, например `lanskoy-pc` |
| `Enter any additional labels` | **Enter, ничего не вводить** — воркфлоу ищет стандартную метку `self-hosted` |
| `Enter name of work folder` | Enter (`_work`) |

Если всё прошло, увидите `√ Runner successfully added` и
`√ Settings Saved.`

## Шаг 3. Проверить, что связь есть

```powershell
.\run.cmd
```

В окне появится:

```
√ Connected to GitHub
Listening for Jobs
```

А в GitHub на странице **Settings → Actions → Runners** ваш раннер загорится
зелёным **Idle**.

Это уже рабочее состояние: пока окно открыто, задания выполняются. Закроете
окно — раннер отключится. Чтобы так не зависеть от окна, идём дальше.

---

## Шаг 4. Сделать службой, чтобы поднимался сам

Закройте окно с `run.cmd` (Ctrl+C), откройте PowerShell **от имени
администратора**, вернитесь в папку и выполните:

```powershell
cd C:\actions-runner
.\svc.cmd install
.\svc.cmd start
```

Теперь раннер живёт службой Windows и запускается вместе с компьютером.
Проверка: `.\svc.cmd status` — должно быть `Running`.

**Важная оговорка про Python.** Служба по умолчанию работает от системной
учётной записи, а не от вашей. Если Python ставился «только для меня» — а
именно так его ставит установщик по умолчанию, и в вашем случае он лежит в
`C:\Users\Misni\AppData\Local\Python\…`, — служба его может не увидеть, и
первый запуск упадёт на шаге «Инструменты» с «Python не найден в PATH
раннера».

Два способа, если это случится:

- переустановить Python с галочкой **Install for all users** — самое простое;
- или не делать службу, а оставить `run.cmd` в открытом окне и положить
  ярлык на него в папку автозагрузки (`Win+R` → `shell:startup`).

Я бы начал со второго: проверить, что всё работает, и только потом
разбираться со службой.

## Шаг 5. Первый запуск

В GitHub: **Actions** → слева **Снимок чужих роликов** → справа
**Run workflow**. Два поля:

- **Сколько роликов взять** — оставьте 5;
- **Или один конкретный ролик** — пусто.

Нажмите зелёную кнопку. Дальше смотрите логи прямо на странице запуска.

Что должно произойти: раннер поставит `yt-dlp` и `numpy`, проверит `ffmpeg`,
скачает пять роликов из свежего `RADAR.md`, измерит каждый, положит в
`Primeri/<канал>-<id>/` кадры, субтитры и `metrics.json`, **удалит видео** и
закоммитит результат. Пять роликов — примерно пять минут, в основном на
скачивание.

Внизу страницы запуска появится сводка по всем разобранным роликам.

## Если что-то пошло не так

| Что видно | Что это | Что делать |
|---|---|---|
| Запуск висит в очереди `Waiting for a runner` | раннер выключен | включить компьютер, проверить `.\svc.cmd status` или открыть `run.cmd` |
| `Python не найден в PATH раннера` | служба не видит пользовательский Python | шаг 4, оговорка про Python |
| `ffmpeg не найден в PATH раннера` | не установлен или PATH не обновился | `winget install Gyan.FFmpeg`, перезапустить службу раннера |
| `Sign in to confirm you're not a bot` | YouTube не поверил, что вы человек | бывает редко с домашнего адреса; подождать час и повторить |
| В логе `нового нет` | все горячие ролики уже разобраны | это не ошибка |

Первый запуск лучше сделать при мне: пришлите ссылку на страницу запуска,
я прочитаю лог и скажу, что поправить.

## Про безопасность, один абзац

Репозиторий публичный, а свой раннер — ваш компьютер. Чужой pull request в
принципе может попытаться выполнить на нём код. Две вещи, которые это
закрывают: в **Settings → Actions → General → Fork pull request workflows**
должно стоять требование одобрения для сторонних (по умолчанию стоит), и наш
воркфлоу вообще не реагирует на события pull request — только расписание и
кнопка. Если репозиторий однажды станет приватным, вопрос снимется сам.
