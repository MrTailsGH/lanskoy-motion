# Сначала звук, потом картинка

Главное правило цеха. Заменяет прежнюю схему «сделали видео → подложили озвучку → подгоняем». Теперь длина ролика и все его тайминги — функция дорожки. Ничего не подрезаем.

---

## Порядок

```
1. Claude даёт сценарий и текст озвучки, разбитый на блоки пустыми строками
2. Пользователь генерит дорожку в eleven_v3 голосом Станислава, присылает mp3
3. Claude выравнивает (align.py) и показывает таблицу с временем каждого блока
4. Пользователь подтверждает раскладку
5. Claude строит сцену ровно под дорожку, рендерит, сводит со звуком
```

Длина ролика не назначается. Сколько наговорил диктор — столько и ролик.

---

## Что нужно от пользователя

**Один файл на ролик.** Не по блокам, не склеенный из кусков — цельная запись. Выравниватель рассчитывает именно на неё.

**Пустые строки между блоками сохранить** при копировании текста: по ним текст делится на блоки. В интерфейсе ElevenLabs абзацы тоже оставить — модель делает на них паузу длиннее.

**Тишину в начале и конце не обрезать.** Уберу сам, по громкости.

**Если мазнуло одно слово — перегенерировать весь файл.** Он короткий, это быстрее, чем чинить склейкой.

Настройки записи — в разделе 7 `OPERATIONS.md`.

---

## Как устроено выравнивание

Распознавание речи не нужно: текст известен заранее. Задача другая — **разложить известные слова по известной дорожке**.

Дорожка превращается в огибающую энергии, 100 замеров в секунду, и дальше в вероятность «здесь речь». Текст превращается в цепочку «слово · пауза · слово · пауза…»: у слова ожидаемая длительность = число слогов × темп, у паузы — приор по знаку препинания.

| Знак | Ожидаемая пауза |
|---|---|
| внутри предложения | 0 |
| запятая | 0,10 с |
| тире | 0,12 с |
| двоеточие | 0,18 с |
| точка | 0,28 с |
| многоточие | 0,45 с |
| пустая строка (граница блока) | 0,55 с |

Дальше динамическое программирование ищет разбиение записи, которое лучше всего согласуется одновременно с громкостью и с этими ожиданиями. Темп подбирается по самой дорожке, поэтому медленный и быстрый диктор обрабатываются одинаково.

**Многоточия в конце блоков больше не нужны.** Они вводились как костыль, когда дорожка резалась по паузам: без них самая короткая пауза между блоками была 0,35 с, а самая длинная внутри блока 0,33 с — запас две сотых секунды, резать нельзя. Выравниватель эту проблему обходит: он не ищет границы по тишине, он их выводит из текста.

## Проверка перед рендером

`align.py` печатает таблицу и две метрики.

```
файл         voice_A.mp3
длина        47.88 с
слов         100   темп 5.94 слог/с (125 слов/мин)
цена         0.135   норма

  #   начало    конец   пауза  проверка  текст
  1     0.08     3.76    0.08         —  Вы наняли человека за восемьдесят тысяч…
  2     4.13     6.41    0.37   100% ok  Считаем, во сколько он обходится
  …

все границы блоков попали в настоящие паузы — раскладке можно верить
```

**Цена** — насколько текст вообще похож на записанное. 0,10–0,15 норма. От 0,25 — начитан не тот текст или брак в записи.

**Проверка** — доля тишины в промежутке перед блоком. Нужно больше 70% при паузе длиннее 0,15 с. Если хоть одна граница не проходит, печатается «ВНИМАНИЕ», и раскладку надо сверять на слух.

Таблицу Claude показывает пользователю **всегда**, до рендера.

## Проверено на реальных дорожках

Один и тот же текст, два голоса:

| | Станислав | Марио |
|---|---|---|
| Длина | 47,88 с | 50,70 с |
| Темп | 125 слов/мин | 118 слов/мин |
| Цена | 0,135 | 0,131 |
| Границы блоков в настоящих паузах | 10 из 10 | 10 из 10 |

Старый инструмент `sync.py`, резавший по паузам, давал 8 из 10 — две границы уезжали на две секунды.

Контрольная точка: после «Вы наняли человека» в дорожке Станислава есть пауза 1,25–1,59 с. Выравниватель ставит конец слова «человека» на 1,26, начало «Договорились» на 1,59.

## Исправленная ошибка

В первой редакции Claude написал, что у дорожки Станислава **1,58 секунды тишины в начале**, и предложил её обрезать. Это неверно:

| Участок | Средняя громкость |
|---|---|
| 0,00–1,23 с | **−21,0 дБ** — это речь |
| 1,23–1,58 с | −52,7 дБ — вот это пауза |

Первая фраза начинается с нулевой секунды. Обрезав 1,58 с, пользователь отрезал бы «Вы наняли человека».

Откуда взялась ошибка: **`ffmpeg silencedetect` не помечает тишину в самом начале файла** — он сообщает только о переходе в тишину. Первое событие в логе было `silence_end: 1.583`, и оно прочиталось как «тишина шла от нуля до 1,58».

Тишину в начале определять по громкости, а не по событиям. И помнить, что `volumedetect` печатает результат на уровне info — флаг `-v error` его глушит.

## Что меняется в сцене

Сейчас в `i01.html` и `i02.html` около сорока жёстко прописанных секунд. При новом порядке они должны стать производными. Наверху сцены появляется объект тайминга:

```js
const T = {
  DUR: 47.88,                    // длина дорожки
  B: [                           // границы блоков из align.py
    [0.08,  3.76],
    [4.13,  6.41],
    …
  ]
};
```

Все внутренние события считаются от границ блока — «строка карточки набегает на четверти блока», а не «на 15,8 секунде». Сцена сама подстраивается под любую дорожку, и перегенерация звука не требует переписывания таймингов.

Это разовая переделка двух готовых сцен. Дальше все 23 оставшихся строятся сразу так.

## Инструменты

```bash
python3 align.py voice.mp3 text.txt timing.json   # основной
python3 sync.py  voice.mp3 text.txt timing.json   # запасной, по паузам
```

`align.py` требует только numpy и ffmpeg — оба уже стоят в контейнере.

`sync.py` оставлен на случай, если выравниватель когда-нибудь не сойдётся: он режет дорожку по n−1 самым длинным паузам и сам считает запас между «паузой на границе» и «паузой внутри блока». Точность заведомо ниже, по умолчанию не используется.
