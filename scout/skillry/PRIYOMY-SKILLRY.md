## 1. Движок и рендер

### 1.1. Motion blur из подкадров — кандидат, у нас не внедрено

Встречается в шести сильных промптах (twoclipping-496100, morse-369333, raphaelaubryy-687877, verbove-268381, thegrootdev-966114, шаблон «UI-морф»): на один выходной кадр рендерится 3–6 подкадров, ffmpeg их смешивает. Текст и всё неподвижное остаются резкими, потому что пиксели совпадают во всех подкадрах. Размывается только то, что движется.

Для наших 30 fps это затвор 180°: четыре подкадра в пределах половины кадра.

```bash
# сцену снять на 120 fps: t = n/120 (render.py сейчас так не умеет — это доработка)
ffmpeg -framerate 120 -i f%05d.png \
  -vf "tmix=frames=4,select='eq(mod(n\,4)\,3)',setpts=N/(30*TB)" -r 30 \
  -c:v libx264 -crf 16 -pix_fmt yuv420p out.mp4
```

Цепочка фильтров проверена на тестовом сигнале: 120 кадров на входе, 30 кадров и 30 fps на выходе. На нашей сцене ещё **не** проверялась.

- Цена: рендер в 4 раза дольше (см. `RENDER-SPEED.md`). Разумно включать только на отрезках быстрого движения: крупный переход, пролёт монеты, свайп.
- Ожидаемый выигрыш: самый резкий кадр у `PER.coin` (сейчас 25%) должен упасть, потому что скачок размазывается по подкадрам. Это ожидание, не замер.
- Авторы подчёркивают «restrained»: блюр только в самой быстрой части, без него на тексте.

### 1.2. Пружины формулой, а не физикой

Пружина считается закрытой формулой отклика на ступеньку, поэтому остаётся чистой функцией `t`. Если цель меняется несколько раз, значение равно **сумме по одной пружине на каждую смену**. Так делают morse-369333, twoclipping-496100 и шаблон «UI-морф».

```js
// критическое затухание, 0 → 1. w = 14: 77% к 0,2 с, 98% к 0,4 с
const spr = (t, w = 14) => t <= 0 ? 0 : 1 - (1 + w * t) * Math.exp(-w * t);
// «tiny overshoot»: z = 0,75 даёт перелёт 2,8%
const sprO = (t, w = 14, z = 0.75) => {
  if (t <= 0) return 0;
  const q = Math.sqrt(1 - z * z), wd = w * q;
  return 1 - Math.exp(-z * w * t) * (Math.cos(wd * t) + z / q * Math.sin(wd * t));
};
// цель меняется в моменты keys: [[t0, v0], [t1, v1], ...]
const track = (t, keys, f = spr) =>
  keys.reduce((v, [ti, vi], i) => i ? v + (vi - keys[i - 1][1]) * f(t - ti) : vi, 0);
// полоса «налог 13% → 15%»: передний край на жёсткой пружине, задний на мягкой —
// полоса вытягивается и догоняет (так у них индикатор таба)
```

У нас сейчас кривые Безье из `perehody.js` и PRIYOMY, часть 5. Пружина нужна там, где цель **меняется по ходу**, например счётчик или полоса, которые дважды переписывают значение. Для одиночного появления хватает нашего `land`.

### 1.3. Контакт-лист до полного рендера

Почти все сильные промпты требуют перед рендером стоп-кадр на каждый бит или 8–20 ключевых кадров одной сеткой. Проверяют: текст обрезан или налезает, висячие слова, контраст, мимо ритма. Контакт-лист у нас уже есть (`snimok.py`, `shot.py`). Новое — **порядок**: сначала лист по фразам дорожки, правка, и только потом 30 fps.

### 1.4. Поиск «хлопков»

twoclipping-496100: после рендера ищется кадр, где разница с соседним **в 3 раза больше, чем у соседей**. Это одиночный скачок, который глаз видит как рывок. Наша метрика «самый резкий кадр» (доля пикселей, сменившихся сильнее 40 уровней) ловит величину. Правило «3× соседей» ловит **одиночность**, поэтому стоит добавить его в `priemka.py` вторым признаком.

Там же: «заливка экрана фигурой должна **уходить за углы кадра и длиться ≈ 0,3 с**, иначе полэкрана меняется за один кадр». Это ровно то, из-за чего 26.09 мы отбросили круг, панель и всплеск.

### 1.5. Грабли браузера из промптов

- Не ставить `opacity` и `filter` на элемент с `preserve-3d`: он сплющивается. Гасить обёртку.
- Не ставить `will-change` на то, что масштабирует камера: текст мылится.
- Дочерний элемент с `visibility: visible` просвечивает сквозь скрытого родителя. Писать `inherit`. У нас слои `PER` прячутся через `visibility`, так что это прямо наш случай.
- Canvas-текстуры рисовать с разрешением **≥ 1,5×** от максимального экранного размера, иначе при наезде будет мыло.
- Крупный CSS-3D-переворот при наезде проецируется в плоскость на весь экран. 3D-повороты — только в WebGL.
- Видео внутри сцены: пережать all-intra (`ffmpeg -g 1`) и ждать `seeked`, либо разрезать в JPEG-секвенцию.
- Случайность — только с зерном (seeded). Экспорт — ровно `[0, длительность)`, без дубля последнего кадра. Никаких сетевых запросов во время рендера.

## 2. Грамматика цифр (CreatorMotion)

Источник — публичные описания 122 паттернов. Сами спецификации платные, мы их не видели. Ниже шесть правил, которые повторяются почти в каждом описании, и что они значат для нас.

1. **Движется только новое.** Всё, что уже на экране, стоит. Единственный движущийся элемент и есть фокус.
2. **Одна мысль — один бит**, у каждого свой интервал чтения. После последнего пункта — пауза, чтобы список прочитался целиком.
3. **Вывод последним**: итог, бейдж или штамп — только после того, как данные «осели».
4. **Шкала не меняется.** Число прикреплено к концу растущего столбика и растёт вместе с ним.
5. **Две фазы:** первая раскладка не исчезает, а сжимается в сторону и становится контекстом для второй.
6. **Число — следствие видимой операции.** Сначала операнды (цена × количество, строки расходов), потом результат. Счётчик в lockstep с тем, что его порождает: карточка добавилась — итог вырос в тот же кадр. Цифры `tabular-nums`, округление до шага валюты.

| Паттерн | Что на экране | Наша тема |
|---|---|---|
| Calculation to Return | умножение → точная сумма → расчёт уходит в сторону → множитель к вложению | «вклад vs ИИС», «сколько принесёт за 3 года» |
| Cost Ledger Total | строки расходов заполняют ведомость, черта, итог | «из чего складывается платёж», «налоги ИП за год» |
| Parts to Whole Equation | слагаемые сходятся в результат | «зарплата = на руки + НДФЛ + взносы» |
| Accumulating Cards and Counter | карточки по одной, счётчик растёт синхронно | «вычеты, которые можно вернуть» |
| Target Overrun | заполнение до линии цели, дальше отдельное «превышение» | лимит дохода самозанятого, пороги шкалы НДФЛ (цифры — только из свежей проверки) |
| Composition Strip | сегменты собираются в одну полосу 100% | «куда уходит зарплата» |
| Ratio Bars | две полосы на одной шкале, скобка «в N раз» | «ставка сейчас vs год назад» |
| Feature Matrix Reveal | заголовки стоят, значения строка за строкой | «ИП vs самозанятый vs ООО» |
| Source Quote Evidence | документ целиком → наезд на фрагмент → маркер по строкам | цитата НК РФ, письмо ФНС — только проверенная |
| Copy Card Correction | неверная фраза зачёркивается, правильная на новой карточке | «миф / как на самом деле» |

Для вертикали 1080×1920 описания и наш опыт совпадают: **горизонтальные полосы** (Ratio Bars, Composition Strip) и **3–5 столбиков**, а не широкие графики. Таймлайн сроков разворачивать сверху вниз.

## 3. Хореография «деньги пришли» (op7418-814408)

Промпт на мобильную игровую награду (сундук). Пять фаз, «ни одну нельзя пропустить». В нашей палитре это поступление денег, одобренный вычет, итог расчёта.

1. **Ожидание.** Объект (у нас `coin-rub` или `piggy`) спокоен, раз в пару секунд вздрагивает.
2. **Апгрейд.** Прыжок, при приземлении сплющивание и отскок. Цвет сменяется на зелёный.
3. **Накопление ≈ 1 с.** Дрожь нарастает, частицы втягиваются к центру, тон звука растёт. В конце резкое сжатие.
4. **Разрядка.** Вспышка из точки (`screen`, интенсивность ≤ 0,8, не в белое), толчок камеры вперёд, три кольца волны (широкое бледное, среднее, тонкое яркое).
5. **Раскрытие.** Сумма прокручивается счётчиком, рядом всплывает «▲ +52 000 ₽». Монеты летят по кривой Безье в «баланс», и баланс подпрыгивает при каждом попадании.

Там же правила, которые пригодятся отдельно:

- Свечение героя — **за** объектом, только по краям. Поверх получается белое пятно.
- Никакой равномерной скорости: squash & stretch, перелёт, упругий возврат.
- Мелкие числа на мелких карточках не писать, детали выносить в панель.
- Конфетти — **один раз**, на кульминации.

**Ограничение для нас:** это «игровой» максимум. По регламенту крупный эффект — один на ролик, как белая вспышка и крупный переход. Фазы 3–4 для финансового ролика ужимать до 0,5–0,7 с, без тряски экрана.

## 4. Камера

- **Непрерывный нырок сквозь масштабы** (ai-ba-reza-113363: дата-центр → сервер → чип → транзистор → атом; dale-vaz-879074: точка на чёрном → окна терминала → точка в космосе → экран телефона). У нас это «зарплата → НДФЛ → бюджет региона» одним планом без склеек. Зум экспоненциальный, длина сегмента ∝ log(зум) — тот же логарифм, что у нашей монеты-пролёта.
- **«Screen Studio» наезд**: камера перекадрирует так, чтобы каждое состояние заполняло кадр. Курсор масштабируется вместе с ней.
- **Фон ведёт** (Living-Halftone): фон стартует на ~0,1 с раньше текста и проходит большее расстояние. Монтаж ощущается ведомым, а не собранным из карточек.
- **Скорость через склейку** (Velocity-Matched UI Sting): уходящий элемент ещё движется в кадре склейки, входящий уже движется по той же оси. Одна ease-семья на вход и её зеркало на выход. План стыков пишется до сборки — «seam ledger»: ось и направление каждой склейки.

## 5. Монтаж, текст, звук

- **Аудио — часы.** Сначала закреплённая дорожка, потом пословные тайминги, из них границы сцен (Chat-to-Result, Partnership). У нас это уже закон цеха (`PIPELINE-zvuk-pervym.md`), здесь — подтверждение со стороны.
- **Работает без звука.** «The story must also work muted»: вшитые субтитры, ключевые слова акцентом.
- **Разведение текста.** Уходящий заголовок исчезает раньше, чем входящий займёт то же место. У текста внутри морфящейся фигуры — свои тайминги входа и выхода.
- **Строка читается до того, как трансформируется.** Пауза полной неподвижности ≥ 400 мс (gdgtify-929495).
- **Кегль — функция длины фразы**: ≤ 3 слов крупно, 4–6 средне, 7+ меньше. Блок не шире 78% кадра. Пустоты в кадре 55–75%, акцент один раз (Frame-Token Editorial).
- **Годы и крупные числа «вбиваются»** пружинным 3D-ударом (rpa-dake-593915). Годится для таймлайна «история рубля».
- **SFX ставить по измеренному пику**, а не по началу файла. Один мягкий звук на каждое появление, в остальное время тишина (aschapmann-724497). Мастер −14 LUFS / −2 dBTP, после кодирования в AAC перемерить (ik-builds-585923). Совпадает с `OPERATIONS.md`.
- **Сетка 120 BPM** — самая частая: 15 кадров на долю при 30 fps. Для речи — не сетка, а лист реплик по фразам и паузам: «не натягивать речь на танцевальный бит».

## 6. Промпт-шаблон для сцены

Лучшие промпты сайта похожи по устройству: XML-разделы, зафиксированный текст, запреты с причиной, план до кода, самопроверка. Переложено на наш цех — пригодится, когда сцену собирает отдельная сессия или субагент:

```text
<inputs>
  дорожка: vhod/<ролик>.mp3, пословные тайминги: timing-<ролик>.json
  текст на экране — ДОСЛОВНО из сценария, не смягчать, не добавлять лозунгов
  цифры — только из PROVERKA/сценария, ни одной своей; нет источника — нет цифры
  палитра и шрифт: design-tokens.json (зелёный = деньги, красный = потеря, бирюзовый = бренд), Golos Text
</inputs>
<direction>
  одна мысль на кадр, много пустоты, один акцент на кадр
  число появляется как следствие видимой операции; вывод последним
  движется только новое; шкала не меняется
</direction>
<structure>
  таймлайн по фразам дорожки: t_in / t_out / что на экране / точная надпись
  один крупный переход на ролик (PER.*), остальное — короткий фейд или свайп
</structure>
<build>
  один HTML 1080×1920, window.seek(t) — чистая функция времени
  без CSS transitions, таймеров, состояния между кадрами, сетевых запросов
  пружины — формулой (spr/track), случайность — с зерном
  Lottie — только через LOT.at(), вписать lottie_pack.py
</build>
<gotchas>
  не will-change на то, что масштабирует камера; visibility: inherit у детей скрытых слоёв
  заливка экрана — за углы кадра и ≥ 0,3 с
  подписи — в safe-зоне вертикали, мерить реальным шрифтом
</gotchas>
<check>
  до рендера: контакт-лист по одному кадру на фразу — обрезы, наложения, контраст
  после: самый резкий кадр и одиночные «хлопки» (3× соседей); починить и перерендерить слабое
  в конце: список решений, которые принял сам
</check>
```

Приёмы формулировок, которые у авторов сработали:

- «покажи план на сетке до того, как писать код»;
- «не отдавай первый черновик — проверь кадры сам и почини»;
- «не выдумывай цифр, процентов, имён — только то, что есть в источнике»;
- запрет с причиной («не ставь opacity на preserve-3d, потому что сплющивает»);
- вехи с критерием: «не иди дальше, пока это не выглядит как надо».

А рамка «это твой шоурил, выложись на полную» даёт эффектный, но неуправляемый результат. Нам не подходит.
