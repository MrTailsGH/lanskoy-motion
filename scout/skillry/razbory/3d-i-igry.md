## 2. Приёмы, которые можно перенести в инфографику

Всё ниже взято из текстов промптов/постов. Пометка «[наше]» — только там, где я связываю приём с нашим форматом; сами параметры не менялись.

### 2.1. Движок кадра: чистая функция времени (прямо совпадает с нашим пайплайном)
- «Every style is computed from time inside seek(t): no CSS transitions, no timers, no state between frames» — twoclipping-496100, morse-369333, raphaelaubryy-687877.
- Пружины — **закрытая формула переходного процесса** (closed-form step response). Значение, у которого цель меняется много раз, = **сумма по одной пружине на каждое изменение** → остаётся чистой функцией t. «Springs everywhere, a tiny overshoot at most» — twoclipping-496100, morse-369333.
- Два края элемента на **разных пружинах**: передний край убегает вперёд заднего, индикатор растягивается (tab indicator, ручка тумблера) — morse-369333. [наше] Годится для растущего столбика/прогресс-бара «налог 13% → 15%».
- Drag как прямое управление: пока «курсор зажат», значение считается из его позиции; при отпускании пружинит обратно от текущего места — morse-369333.
- Детерминизм захвата: «render the same frame twice, get identical pixels» — aayush4soni-644283.
- curieuxexplorer-772215: 30-секундный ролик = 900 кадров (т.е. 30 fps), 30+ звуков «из чистой математики», 1850 строк.

### 2.2. Рендер и контроль качества
- Motion blur: **4 подкадра на кадр, смешать `ffmpeg tmix`, 60 fps** — twoclipping-496100, morse-369333.
- Вариант: **3 подкадра — t − 1/240 с, t, t + 1/240 с**, затем tmix, 60 fps — raphaelaubryy-687877. [наше] У нас 30 fps: параметры в промптах даны для 60 fps, шаг подкадра придётся подбирать самим.
- Перед полным рендером: «Render one frame per beat before the full render» (morse-369333); «Probe 20 or more frames» (raphaelaubryy-687877); затем **поиск одиночных «хлопков»: скачок разницы кадров в 3× больше соседей** — twoclipping-496100.
- Видео внутри сцены: пережать **all-intra (`ffmpeg -g 1`)**, грузить как blob URL, ждать `'seeked'` перед отрисовкой кадра (twoclipping-496100); либо разрезать клипы в **JPEG-секвенции 30 fps** и менять src у img, seek ждёт декодирования (raphaelaubryy-687877). `python http.server` не умеет range-seek видео — поэтому blob URL (twoclipping-496100).

### 2.4. 3D-объект-герой (монета, копилка, сейф, медаль) — op7418-814408 (= op7418-818226)
- Настоящий 3D в Three.js, не плоский SVG: толщина, **фаска**, структурные детали (швы досок, заклёпки, окантовка, грани камня, замок) — **настоящей геометрией**, не нарисованными линиями.
- Тонирование: **MeshToonMaterial + градиентная карта на 3–4 ступени**; **три источника света: key, sky (небо), rim-свет цвета уровня**.
- Обводка — постобработка: рендер **normal map + depth map**, линии шейдером; внешний контур толще, стыки деталей тоньше; **1,5× суперсэмплинг + MSAA**. Порог по глубине ослабить, швы — в основном по нормалям (иначе на косых поверхностях рябь). Не использовать «увеличенную чёрную изнанку» — толщина неровная, углы рвутся.
- Idle: медленный поворот влево-вправо (видно толщину) + лёгкое покачивание вверх-вниз; мягкая тень под объектом, зависящая от высоты.
- Движущиеся части двигаются физически: крышка на петле, медаль вокруг вертикальной оси.
- Свечение героя — **за объектом**, только выглядывает по краям; не поверх (иначе белое пятно). Орбита звёздной пыли — строго снаружи силуэта.
- Во время финального «reveal» спрятать остальные 3D-объекты, иначе пост-обводка нарисует их контуры на фоне.
- Материалы UI: градиент «шлифованный металл», фаска светлее слева-сверху / темнее справа-снизу, внутренняя тень; инкрустации по уровню (стальные заклёпки → серебро с камнем → золото с бриллиантом и короной).
- Палитра по уровням (пример из промпта): обычный зелёный → редкий синий → эпический фиолетовый → легендарный золотой; с уровнем меняются основной цвет, цвет света и фон. Единая тёмная обводка, пример **#1A1033**.
- Заголовки: круглый «игровой» шрифт (Titan One / Lilita One), чёрная обводка, тень; буквы «вбиваются» по одной с отскоком.
- bthreeagency-827092: бейдж как **твёрдое 3D-тело, наклоняется к курсору по физике**, празднование **золотыми частицами**, «fast and smooth, it should not be bouncy».

### 2.5. Хореография «награды» — прямо переносится на «деньги пришли / вычет одобрен» (op7418-814408)
Пять фаз, «缺一不可» (ни одну нельзя пропустить):
1. Ожидание: объект парит, раз в несколько секунд вздрагивает.
2. Апгрейд: прыжок, оборот в воздухе, **сплющивание при приземлении и отскок**; смена цвета уровня, вспышка, кольцо частиц, новый заголовок.
3. Накопление **≈1 с**: дрожь всё сильнее, из щелей пробивается свет, частицы **втягиваются к центру**, тон звука растёт; в конце резкое сплющивание.
4. Взрыв: радиальный bloom-вспышка из точки взрыва (**mix-blend-mode: screen, интенсивность ≤ 0,8**, без полного белого), тряска экрана, **толчок камеры вперёд**, многослойные ударные волны, длинные световые штрихи, искры, **монеты и камни с вращением**. Конфетти — **один раз** на кульминации.
5. Раскрытие: карточки награды вылетают **по дуге**, при посадке — overshoot и покачивание; **цифры прокручиваются счётчиком**; в инфопанели цифры растут и всплывает «**▲+значение**»; затем **монеты летят по кривой Безье в баланс справа сверху, баланс подпрыгивает при каждом попадании**.
- На мелких карточках не писать мелкие числа — детали в панели при раскрытии.
- Свет без жёстких краёв: фоновые лучи — **conic-gradient с плавными переходами, 2–3 слоя разной плотности и скорости вращения**; световые столбы — **5–7 размытых лучей веером**, каждый слегка мерцает, у корня мягкое ядро, внутри медленно всплывает пыль.
- Частицы: у каждой искры — ореол низкой прозрачности; ударная волна — **три обводки: широкая бледная, средняя, тонкая яркая**.
- Частицы на Canvas 2D своими силами: гравитация, сопротивление, время жизни, аддитивное смешивание; три движения — «втягивание», «полёт по кривой», «орбита».
- Все движения со squash & stretch, overshoot, упругим возвратом; «不要匀速» (никакой равномерной скорости).
- Самопроверка: снимки в моменты накопления, взрыва, раскрытия, итога; вопросы: не закрыт ли герой ореолом/частицами/текстом? нет ли пересвета? нет ли лишних контурных линий? читается ли мелкий текст? не дрожит ли что-то после итога?
- [наше] Промпт написан под GSAP-таймлайн и Web Audio в реальном времени — для нас всё это нужно пересчитать в seek(t).
