# Пульт цеха

Локальная страница вместо командной строки: видно состояние всех роликов,
свежий радар, разборы чужих роликов и последние запуски на GitHub, а
процессы запускаются кнопкой.

## Запуск

**Windows** — двойной клик по `PULT.bat` в корне репозитория.
**Мак и контейнер** — `bash pult.sh`.

Откроется `http://127.0.0.1:8765/`. Закрыть — Ctrl+C в том же окне.

Ставить ничего не нужно: только стандартная библиотека Python. Порт можно
сменить: `python3 pult/pult.py --port 9000`.

## Что показывает

- **Инструменты** — что есть на этой машине: ffmpeg, node, yt-dlp,
  playwright. Кнопка, которой не хватает инструмента, гаснет сама.
- **Процессы** — десять задач, у каждой живой лог прямо в карточке.
- **Приёмка** — наши ролики против нормы, посчитанной из чужих разборов:
  громкость, покой, склейки, длительность движения, плотность звука. Судится
  готовый ролик — сведённый со звуком, если он есть.
- **Телеграм** — пост дня из `TG-30-dney.md` с промптом картинки и кнопками
  «скопировать». Галка «запостил» отмечает опубликованное: полоска из
  тридцати дней показывает разом, что сделано и что пропущено, счётчик
  считает, а пульт открывается на первом незапощенном дне. Отметил — сразу
  листает к следующему.

  Отметки лежат в `pult/otmetki.json` на машине и **в репозиторий не едут**.
  Это не небрежность: отслеженный день в истории ломал бы `git pull
  --ff-only` при следующем обновлении. Чистить браузер можно, отметки
  переживут — они на сервере, а не в нём.
- **Ролики** — шесть стадий на каждый ролик (текст, дорожка, тайминги,
  сцена, ролик, сведённый звук) и превью готовых MP4 прямо на странице.
- **Радар** — верхушка выбросов полосами: просмотры, делённые на медиану
  канала. У роликов, которые растут между снимками, рядом спарклайн роста.
  Ниже — весь `RADAR.md` текстом.
- **Ритм** — лента времени каждого ролика на общей шкале: серые столбики —
  движение в кадре (высота равна величине изменения), красные линии —
  жёсткие склейки, бирюзовые точки — переходы с расфокусом. Под чертой те же
  секунды для наших роликов: блоки дорожки из `timing-*.json`, промежутки
  между ними — паузы. Наведите на любую марку — покажет секунду и подробность.
- **Разборы** — кадр и числа из каждого `metrics.json`: склейки, покой,
  громкость, плотность звука, дрейф, расфокус на переходах.
- **GitHub** — восемь последних запусков воркфлоу с цветом и ссылкой.
  Репозиторий открытый, поэтому ключ не нужен.

## Куда девается наработанное

**Разборы чужих роликов едут сами** — у карточек «Снимок» и «Разбор по
ссылке» стоит галка «отправить в репозиторий».

**Всё остальное остаётся на машине.** Радар пишет `radar/RADAR.md` и
`history.json`, приёмка — `priemka/`, «Принять дорожку» правит
`timing-*.json` и сцену. Эти файлы ждут на диске, пока их не отправить.

Поэтому в полосе версии стоит счётчик **«не отправлено: N»** и кнопка
**Отправить** рядом. Она же есть карточкой в процессах.

Копить нельзя не только из-за сохранности: обновление идёт через `git pull
--ff-only`, и он откажется работать, когда на машине лежат неотправленные
правки тех же файлов. Копится молча — отваливается разом.

**Стереть наработанное обновление не может.** `--ff-only` именно этим и
выбран: при расхождении он останавливается и ничего не трогает. Папка
раннера (`C:\actions-runner\_work\…`) — другая, отдельная копия, её GitHub
действительно чистит перед каждым запуском; к папке пульта это отношения
не имеет.

## Обновление

Само, при каждом запуске: `PULT.bat` и `pult.sh` делают `git pull --ff-only`
перед стартом. Ключ выбран сознательно — если на машине правили файлы руками,
обновление честно откажется, а не устроит слияние с конфликтами за спиной.
Неудачное обновление запуску не мешает: пульт поднимется на том, что есть.

Под шапкой видно версию и дату. Пульт раз в две минуты спрашивает GitHub про
последний коммит: если на машине старее — появляется метка «на GitHub есть
свежее» и кнопка **Обновить** рядом. Та же задача есть карточкой в процессах.

**После обновления пульт надо перезапустить.** Сервер читает свой код один
раз при старте и дальше работает по нему, поэтому свежие правки в `pult.py`
на лету не подхватятся. Молчать об этом было бы враньём: страница сама
выводит синюю полосу «Пульт обновился, но работает по старому коду».

## Когда YouTube закрыт

ВПН-расширение **в браузере пульту не помогает**: страница только отдаёт
команду, а качает отдельный процесс на машине, мимо браузера. Два выхода.

**Пустить через ВПН сам Python.** В приложении ВПН включить режим «на всю
систему» либо добавить в список программ `python.exe`. После этого пульт
перезапустить — маршруты процесс берёт при старте, на лету не подхватит.

**Или принести файл руками.** Скачать ролик браузером, где ВПН работает,
положить в папку `vhod/` — и нажать **«Разобрать свой файл»**. Считается всё
то же самое: склейки, переходы, покой, громкость, дрейф. Субтитры
подхватятся, если лежат рядом с тем же именем.

Поле **прокси** на карточках снимка и разбора — для случая, когда ВПН
показывает локальный порт (`socks5://127.0.0.1:1080`). Адрес запоминается
в браузере и подставляется в обе карточки.

## Чего пульт не делает

Не выполняет произвольные команды. Браузер присылает только имя задачи из
списка в `pult.py` и проверенные параметры — номер ролика из перечня,
число роликов от одного до двадцати, ссылку строго на YouTube. Список
задач правится в самом `pult.py`, в словаре `ZADACHI`.

Слушает только `127.0.0.1` — из сети к пульту не подключиться.

## Где что лежит

- `pult/pult.py` — сервер и список задач.
- `pult/index.html` — страница.
- `pult/logi/` — логи запусков, по файлу на задачу. В репозиторий не едут.

## Что где выполняется

Сборка ролика и рендер требуют bash, node и ffmpeg — это контейнер.
На домашней машине работают радар, снимок, разбор и сводка. Кнопки, для
которых нет инструментов, гаснут, а не падают на полпути.
