# Пульт цеха

Локальная страница вместо командной строки: видно состояние всех роликов,
свежий радар, разборы чужих роликов и последние запуски на GitHub, а
процессы запускаются кнопкой.

## Запуск

**Windows** — двойной клик по `PULT.bat` в корне репозитория.
**Мак и контейнер** — `bash pult.sh`.

Откроется `http://127.0.0.1:8765/`. Закрыть — Ctrl+C в том же окне.

Ставить ничего не нужно: только стандартная библиотека Python. Порт можно
сменить: `python3 pult/pult.py --port 9000`.

## Что показывает

- **Инструменты** — что есть на этой машине: ffmpeg, node, yt-dlp,
  playwright. Кнопка, которой не хватает инструмента, гаснет сама.
- **Процессы** — семь задач, у каждой живой лог прямо в карточке.
- **Ролики** — шесть стадий на каждый ролик (текст, дорожка, тайминги,
  сцена, ролик, сведённый звук) и превью готовых MP4 прямо на странице.
- **Радар** — когда считан отчёт, сколько снимков в истории, и сам
  `RADAR.md` целиком.
- **Разборы** — кадр и числа из каждого `metrics.json`: склейки, покой,
  громкость, плотность звука, дрейф, расфокус на переходах.
- **GitHub** — восемь последних запусков воркфлоу с цветом и ссылкой.
  Репозиторий открытый, поэтому ключ не нужен.

## Чего пульт не делает

Не выполняет произвольные команды. Браузер присылает только имя задачи из
списка в `pult.py` и проверенные параметры — номер ролика из перечня,
число роликов от одного до двадцати, ссылку строго на YouTube. Список
задач правится в самом `pult.py`, в словаре `ZADACHI`.

Слушает только `127.0.0.1` — из сети к пульту не подключиться.

## Где что лежит

- `pult/pult.py` — сервер и список задач.
- `pult/index.html` — страница.
- `pult/logi/` — логи запусков, по файлу на задачу. В репозиторий не едут.

## Что где выполняется

Сборка ролика и рендер требуют bash, node и ffmpeg — это контейнер.
На домашней машине работают радар, снимок, разбор и сводка. Кнопки, для
которых нет инструментов, гаснут, а не падают на полпути.
