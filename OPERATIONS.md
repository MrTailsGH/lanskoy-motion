# Регламент цеха

Рабочие знания проекта. Файл живёт в репозитории намеренно: он привязан к аккаунту, а не к компьютеру, и читается при каждом клоне. Claude открывает проект с новой машины — начинать отсюда.

Последнее обновление: 16.09.2026, вечер.

---

## 0. Порядок работы: сначала звук, потом картинка

Это главное правило цеха, всё остальное из него следует.

```
1. Claude пишет сценарий и текст озвучки
2. Пользователь генерит дорожку в ElevenLabs и присылает mp3
3. Claude выравнивает текст по дорожке (align.py) и показывает таблицу
4. Пользователь подтверждает — Claude строит сцену ровно под дорожку
5. Рендер, сведение со звуком, один файл на выходе
```

**Длина ролика не назначается заранее.** Сколько наговорил диктор — столько и ролик. Подрезать и растягивать ничего не нужно. Прежний канон «46 секунд» отменён: это была длина картинки, под которую подгонялся текст.

Регламент подробно — `PIPELINE-zvuk-pervym.md`.

## 1. Как рендерятся ролики

**Контейнер Claude. Единственный путь, проверено, работает.**

```
сцена .html со window.seek(t) → покадровый Chromium → ffmpeg → MP4
```

**Контейнер больше не приходит готовым.** 16.09.2026 сессия открылась без
numpy, без playwright, без ffmpeg в `PATH` и без шрифтов Golos Text. Раньше
они были предустановлены — рассчитывать на это нельзя. Первым делом в новой
сессии:

```bash
bash setup.sh
```

Скрипт ставит numpy, playwright и ffmpeg через pip, а шрифты — через npm из
`@expo-google-fonts/golos-text` (полные TTF, имена гарнитур точно те, что
ждёт сцена: `Golos Text`, `Golos Text Medium`, `Golos Text SemiBold`,
`Golos Text Black`). Проверять: `fc-list | grep -i golos` — должно быть 6.

**Грабли контейнера, на которые ушло время:**

- `@fontsource/golos-text` не годится: там woff2 и порезанные на подмножества
  файлы, все с именем «Golos Text Regular». `fc-cache` их не разложит по
  начертаниям. Нужен `@expo-google-fonts/golos-text`.
- Chromium в `/opt/pw-browsers` может не совпадать по ревизии с установленным
  playwright. Тогда `launch()` требует `playwright install`, которого делать
  нельзя. Путь к двоичному файлу ищет `browser.py`, все три скрипта рендера
  ходят через него.
- ffmpeg отдельно ставить не надо: он лежит внутри пакета `imageio-ffmpeg`.

**Замер:** 1380 кадров (46 с, 30 fps, 1080×1920) — рендер 8 минут, файл 9,6 МБ.

**Важно про лимит вызова.** Рендер длиннее 10 минут не влезает в один вызов Bash. Запускать через `nohup python3 render.py > render.log 2>&1 &` и опрашивать лог. `render.py` умеет докатывать: уже готовые кадры пропускает, поэтому прерванный рендер продолжается с места обрыва.

**Сборка:**
```bash
ffmpeg -y -framerate 30 -i frames/f%05d.png \
  -c:v libx264 -preset slow -crf 16 -pix_fmt yuv420p -profile:v high -level 4.2 \
  -x264-params "deblock=-1,-1:aq-mode=3:aq-strength=1.1" -movflags +faststart -r 30 out.mp4
```

**Сведение со звуком:**
```bash
ffmpeg -y -i out.mp4 -i voice.mp3 -c:v copy -c:a aac -b:a 192k -shortest final.mp4
```

**Remotion больше не используется.** Рендер в GitHub Actions был первым подходом; локальный конвейер быстрее и не требует ничего заливать. Наследство того подхода (`Root.tsx`, `Skidka20.tsx`, `anim.ts`, `ui.tsx`, `theme.ts`, `index.ts`, `package.json`, `remotion.config.ts`, `tsconfig.json` и workflow `.github/workflows/render.yml`) **удалено 16.09.2026**. Понадобится — лежит в истории git до коммита `3d91baa`.

## 2. Обязательное условие сцены

Всё состояние — **чистая функция одного `t`** (секунды). Экспортируется как `window.seek(t)` и `window.META = {FPS, DUR, FRAMES}`. Никаких CSS-анимаций и переходов: при покадровом захвате они недетерминированы и дают дрожание.

**Второе условие, введено 16.09.2026: время живёт в объекте `T` наверху файла.**

```js
const T = { src:"голос.mp3", DUR:47.88, B:[[0.32,4.11],[4.55,6.40], …] };
```

`B` — границы блоков дорожки, ровно то, что выдаёт `align.py`. Абсолютных
секунд в коде сцены нет: события считаются от блоков.

```js
bs(i), be(i)        начало и конец блока i (нумерация с единицы)
at(i,p)             доля p внутри блока i
enter(i,d)          вход акта за d секунд до блока, но не раньше,
                    чем договорён предыдущий блок
gone(i,next)        уход акта: держим всю паузу, убираем к приходу
                    следующего акта
```

Подставляет тайминг `settime.py`, руками объект не править.

**Блоков меньше, чем актов — это нормально.** В И-02 блок 8 «Чтобы заработать
столько же… Три клиента вместо одного» держит сразу два акта: столбики и
человечков. Граница ставится долей — `at(8,0.56)`, ровно на «Три клиента», —
и уход первого акта считается от неё, а не от конца блока. Дробить текст
озвучки под картинку нельзя: паузы диктора важнее.

**Почему `enter` и `gone` именно такие.** Первая версия считала вход как
«за 0,4 с до блока», а уход как «через 0,3 с после». На паузе короче 0,4 с
два акта оказывались на экране одновременно — «СЧИТАЕМ, ВО СКОЛЬКО ОН
ОБХОДИТСЯ» поверх чисел разрыва. На паузе длиннее секунды выходило
обратное: картинка уходила, титр висел над пустым экраном. Вход обязан
упираться в конец предыдущего блока, уход — в приход следующего акта.

**Сцену можно строить до записи дорожки.** `settime.py --estimate` кладёт
оценку по темпу Станислава, сцена рендерится и проверяется. Когда придёт
mp3, оценка заменяется настоящей раскладкой одной командой — переписывать
сцену не нужно.

## 4. Структура ролика-инфографики

Порядок жёсткий. Ролик, начинающийся сразу с числа, не работает: зритель листает не от пустого экрана, а от непонимания, о чём это.

```
постановка   узнаваемая ситуация во втором лице, НОЛЬ цифр
обещание     начинается словом «считаем» + четыре статьи расчёта
разрыв       число, буквально противоречащее постановке
расчёт       карточка заполняется построчно
главное число
белая вспышка — смена акта, ровно одна на ролик
второй акт
CTA, картинка возвращается к началу (петля)
```

Доли даны без секунд намеренно: границы берутся из дорожки. Готовые постановки и обещания для всех 15 — в `PACK-01-otkrytiya.md`.

## 5. Вёрстка вертикали

**Безопасные поля** (соглашение проекта, не опубликованный стандарт площадок): верх 0–240, низ 1400–1920, правый край 880–1080. Рабочее поле `x 60…820 · y 240…1400`. Оптический центр — **y 780**, не 960.

**Сетка.** Титр y 258–458. Карточка y 516–1230. Крупное число y 640–1000. Пилюли выбора — под карточкой, y ~1128. Футер y 1318 и 1356.

**Грабли, на которые уже наступили:**

- Числа вида «134 000 ₽» при кегле выше ~130 не влезают в колонку 760 px и переносят знак рубля на вторую строку. Ставить `whiteSpace: nowrap`.
- Титр обязан укладываться в две строки. Кегль подбирается функцией `fitCaption` от 76 px вниз с шагом 2, результат кешируется по тексту. Без этого титр наезжает на карточку.
- Строки карточки ниже 122 px наезжают друг на друга.
- Межстрочные интервалы всех строк карточки должны быть равны, иначе разнобой виден.
- Крупный итог поверх карточки требует затемняющей подложки `rgba(10,13,12,.93)`, иначе цифры карточки просвечивают.
- **Пилюли выбора нельзя ставить над карточкой** — они бьют по титру. Место под карточкой, y ~1128.
- Столбики и любой нижний блок держать выше y 1300, иначе накрывают строку расчёта в футере.
- Эхо-строка петли на CTA не должна накладываться на текст CTA.
- Служебные подписи — в одном регистре. Капс.
- **ЛАНСКОЙ пишется с заглавной.** Это фамилия персонажа.

**Полосы на градиенте.** В 8-битном H.264 плавный градиент даёт видимые ступени. Лечится зерном: тайловый PNG-шум 180×180 (нормальное распределение, σ≈26) как data-URI, `opacity .055`, `mix-blend-mode: overlay` поверх фона. Плюс более пологий градиент и `crf 16` с `deblock=-1,-1:aq-mode=3`.

## 6. Визуальный язык

- Тёмный фон `#0A0D0C` с зелёным радиальным свечением.
- **Зелёный `#2FD38E` — деньги, красный `#F0524D` — потеря, бирюзовый `#3FB7C9` — бренд.** Других значений у цвета нет.
- Титр пословно сверху, caps, **Golos Text Black**. Лейблы — Medium и SemiBold.
- «Карточка приложения» по центру: мелкий caps-лейбл с цветной точкой, под ним крупное число. Зритель верит цифре, которая стоит в интерфейсе.
- Лейблы всех строк карточки видны с самого начала серым, значения набегают по таймлайну. Иначе карточка первые секунды выглядит пустой коробкой.
- Пилюли выбора, активная зеленеет — визуальный «клик».
- Белая вспышка — маркер смены акта. Одна на ролик.
- Одно крупное число на ролик. Два — и ни одно не запомнится.
- Ни одного статичного кадра длиннее 2,5 секунды.

## 7. Озвучка

**Модель — `eleven_v3`.** Проверено 16.09.2026: ударения и числительные читаются правильно. Multilingual v2 для русского не годится — в ней нет управления произношением (phoneme-теги работают только в `eleven_flash_v2` и `eleven_v3`, IPA/CMU для неанглийских языков — только в `eleven_v3`). На канале не используется.

**Голос — Станислав** (Stanislav · Deep, Empathetic and Warm). Зафиксирован на все 25 роликов. Менять нельзя: лента должна звучать одним человеком, иначе придётся переозвучивать всё.

Stability 55, similarity 80, style exaggeration 0, speaker boost выключен, speed 1.0. Аудио-теги не добавляем — ролики про арифметику, ровное чтение важнее выразительности.

**Три правила текста, обязательны для всех роликов:**

1. **Аббревиатуры голосом не произносятся.** «НДФЛ» → «налог», «МСП» → «малый бизнес». Сама аббревиатура остаётся на экране. Запись по буквам (`эн-дэ-эф-эл`) проверена и не работает.
2. **Точность на экране, смысл в голосе.** Составные числительные округляются: экран 27 600 ₽ → голос «почти двадцать восемь тысяч»; экран 247 → «почти двести пятьдесят». Ни одного числительного длиннее двух слов. Числа — всегда словами, цифрами писать нельзя: автонормализация мажет падежом.
3. **Слова с подвижным ударением под запретом** — прежде всего «стоит» (сто́ит / стои́т) и «вдвое». «День работы стоит N» переписывается как «один его рабочий день — N».

**Многоточия в конце блоков отменены.** Они вводились, чтобы можно было резать дорожку по паузам; с появлением `align.py` не нужны. Текст пишется обычными знаками препинания, блоки разделяются пустой строкой.

**Темп Станислава — 125 слов в минуту (2,1 слова в секунду).** Для прикидки хронометража: 101 слово ≈ 48 секунд вместе с паузами. Бюджет 2,2 слова на секунду остаётся рабочей оценкой при написании текста.

Генерировать **одним файлом на ролик**, тишину в начале и конце не обрезать.

**Запасной путь, если текстовых правил не хватит:** pronunciation dictionary с IPA внутри ElevenLabs, либо Yandex SpeechKit — там ударение задаётся знаком `+` перед ударной гласной (`зам+ок`), паузы `sil<[300]>` до 7000 мс, акцент `<[accented]>`, фонемы `[[...]]`. Текст И-01 с расставленными ударениями лежит в `OZVUCHKA-I-01.md`.

## 8. Выравнивание текста по дорожке — `align.py`

Не распознавание речи. Текст известен заранее, задача — найти, где какое слово прозвучало.

```bash
python3 align.py voice.mp3 text.txt timing.json
```

Нужны только **numpy и ffmpeg**, оба уже стоят. Ставить нечего.

**Как устроено.** Дорожка → огибающая энергии 100 кадров/с → вероятность «здесь речь» (логистика от порога `floor + 0.42·(peak−floor)`, наклон `span/9` дБ). Текст → цепочка единиц «слово · пауза»: длительность слова = число слогов × темп, длительность паузы = приор по знаку препинания (`,` 0,10 с · `—` 0,12 · `:` 0,18 · `.` 0,28 · `…` 0,45 · пустая строка 0,55). Сшивка — динамическое программирование с явной длительностью, штрафы `K_WORD=9` (квадрат логарифма отношения) и `K_GAP=4`.

**На выходе** JSON: длина дорожки, цена, границы каждого блока и время начала-конца **каждого слова**.

**Две метрики самопроверки, обе печатаются:**

| | Норма | Что значит отклонение |
|---|---|---|
| Цена | 0,10–0,15 | от 0,25 — начитан не тот текст или брак в записи |
| Тишина на границах блоков | >70% и пауза >0,15 с | иначе печатается «ВНИМАНИЕ», раскладку сверять на слух |

**Проверено на реальных дорожках:** Станислав 47,88 с, цена 0,135; Марио 50,70 с, цена 0,131. Границы блоков — **10 из 10** попали в настоящие паузы у обоих.

Контрольная точка: в дорожке Станислава после «Вы наняли человека» пауза 1,25–1,59 с. Алайнер ставит конец слова «человека» на 1,26, начало «Договорились» на 1,59.

**Таблицу показывать пользователю до рендера.** Всегда.

После подтверждения таблицы раскладка уходит в сцену:

```bash
python3 settime.py i01.html timing.json
```

`sync.py` — предыдущий инструмент, резал по паузам. Давал 8 блоков из 10 (пауза между предложениями и пауза между абзацами по уровню сигнала неразличимы). Оставлен в репозитории как запасной, по умолчанию не используется.

## 11. Заливка в репозиторий через браузер

Рабочий порядок, проверен трижды:

1. `list_connected_browsers` → `select_browser` по deviceId (браузер пользователя — **Brave**).
2. Открыть `https://github.com/MrTailsGH/lanskoy-motion/upload/main`.
3. `find` «file input element for choosing files» → `file_upload` со списком путей из `/mnt/user-data/outputs/…`. **До 10 МБ за вызов.**
4. Кликнуть по полю сообщения коммита, напечатать текст.
5. Кнопка «Commit changes» кликается **по координате**, может не сработать с первого раза — проверять скриншотом.
6. Сверить результат клоном и контрольными суммами.

**Грабли:**

- `navigate` без явного `tabId` иногда рапортует успех, а вкладка остаётся на `chrome://newtab`. Навигировать с `tabId` или создать новую вкладку.
- `deviceId` браузера меняется при переподключении. Старый не переиспользовать.
- Если `file_upload` упал с «extension disconnected mid-operation», файл всё равно мог прикрепиться. Проверить список и удалить дубликат: кнопка «Remove <имя файла>» ищется через `find`, клик по ref.
- После клика по крестику страница может внезапно оказаться сильно зазумленной, и `Page.captureScreenshot` отваливается по таймауту. Работать через `find` и клики по ref вместо координат.
- `file_upload` принимает пути контейнера `/mnt/user-data/outputs/…`. Пути подключённой папки `C:\…` — **не принимает**.
- Кириллицу из имён файлов убирать: веб-загрузка GitHub её иногда ломает.
