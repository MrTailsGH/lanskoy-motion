# Регламент цеха

Рабочие знания проекта. Файл живёт в репозитории намеренно: он привязан к аккаунту, а не к компьютеру, и читается при каждом клоне. Claude открывает проект с новой машины — начинать отсюда.

Последнее обновление: 16.09.2026, вечер.

---

## 0. Порядок работы: сначала звук, потом картинка

Это главное правило цеха, всё остальное из него следует.

```
1. Claude пишет сценарий и текст озвучки
2. Пользователь генерит дорожку в ElevenLabs и присылает mp3
3. Claude выравнивает текст по дорожке (align.py) и показывает таблицу
4. Пользователь подтверждает — Claude строит сцену ровно под дорожку
5. Рендер, сведение со звуком, один файл на выходе
```

**Длина ролика не назначается заранее.** Сколько наговорил диктор — столько и ролик. Подрезать и растягивать ничего не нужно. Прежний канон «46 секунд» отменён: это была длина картинки, под которую подгонялся текст.

**Единственная добавка — хвост под CTA.** ElevenLabs иногда срезает тишину в
конце вплотную к последнему слову: у дорожки И-01 последнее слово кончается
на 42,52, а файл длится 42,53. Тогда CTA живёт секунду, а эхо-строку петли
прочитать невозможно. Лечится ключом `--tail` у `settime.py`: голос кончился,
картинка ещё держится. Для И-01 взято 1,4 с. Это не растягивание ролика под
картинку — это пауза после точки.

Регламент подробно — `PIPELINE-zvuk-pervym.md`.

## 1. Как рендерятся ролики

**Контейнер Claude. Единственный путь, проверено, работает.**

```
сцена .html со window.seek(t) → покадровый Chromium → ffmpeg → MP4
```

**Контейнер больше не приходит готовым.** 16.09.2026 сессия открылась без
numpy, без playwright, без ffmpeg в `PATH` и без шрифтов Golos Text. Раньше
они были предустановлены — рассчитывать на это нельзя. Первым делом в новой
сессии:

```bash
bash setup.sh
```

Скрипт ставит numpy, playwright и ffmpeg через pip, а шрифты — через npm из
`@expo-google-fonts/golos-text` (полные TTF, имена гарнитур точно те, что
ждёт сцена: `Golos Text`, `Golos Text Medium`, `Golos Text SemiBold`,
`Golos Text Black`). Проверять: `fc-list | grep -i golos` — должно быть 6.

**Грабли контейнера, на которые ушло время:**

- `@fontsource/golos-text` не годится: там woff2 и порезанные на подмножества
  файлы, все с именем «Golos Text Regular». `fc-cache` их не разложит по
  начертаниям. Нужен `@expo-google-fonts/golos-text`.
- Chromium в `/opt/pw-browsers` может не совпадать по ревизии с установленным
  playwright. Тогда `launch()` требует `playwright install`, которого делать
  нельзя. Путь к двоичному файлу ищет `browser.py`, все три скрипта рендера
  ходят через него.
- ffmpeg отдельно ставить не надо: он лежит внутри пакета `imageio-ffmpeg`.

**Замер:** 1380 кадров (46 с, 30 fps, 1080×1920) — рендер 8 минут, файл 9,6 МБ.

**Важно про лимит вызова.** Рендер длиннее 10 минут не влезает в один вызов Bash. Запускать через `nohup python3 render.py > render.log 2>&1 &` и опрашивать лог. `render.py` умеет докатывать: уже готовые кадры пропускает, поэтому прерванный рендер продолжается с места обрыва.

**Сборка:**
```bash
ffmpeg -y -framerate 30 -i frames/f%05d.png \
  -c:v libx264 -preset slow -crf 16 -pix_fmt yuv420p -profile:v high -level 4.2 \
  -x264-params "deblock=-1,-1:aq-mode=3:aq-strength=1.1" -movflags +faststart -r 30 out.mp4
```

**Сведение со звуком:**
```bash
ffmpeg -y -i out.mp4 -i voice.mp3 -c:v copy -c:a aac -b:a 192k final.mp4
```

**Без `-shortest`.** Картинка теперь длиннее звука на хвост под CTA, и резать
её по звуку нельзя. Лишнего не будет: ffmpeg заканчивает, когда кончились оба
входа, а звук просто замолкает раньше.

**И без `apad`.** Дотянуть звук тишиной до длины картинки — первое, что
приходит в голову, и именно оно вешает ffmpeg намертво: `apad` генерирует
бесконечную тишину, а `-shortest` при фильтре её не обрывает. Процесс живёт,
файл не растёт, ошибки нет. Проверено 16.09.2026 на сведении И-01: три
минуты впустую, тогда как правильная команда отрабатывает за полторы
секунды.

### Два пути рендера

**Локально в контейнере** — то, что описано выше. Быстро проверить кадр,
посмотреть правку, снять контрольный лист. Скорость — 1,5 кадра в секунду,
полный ролик около 15 минут.

**В облаке, GitHub Actions + Remotion** — основной путь для готового ролика.
Кнопка Run workflow в репозитории, на выходе MP4 в артефактах запуска.
Claude-сессия для этого не нужна вовсе.

Замерено на живом запуске 16.09.2026, И-01, 1374 кадра без звука:

| шаг | время |
|---|---|
| шрифты Golos Text | 3 с |
| `npm ci` (с кэшем) | 6 с |
| скачать chrome-headless-shell | 3 с |
| **рендер 1374 кадров** | **2 мин 55 с** |
| сборка ffmpeg и сведение | 48 с |
| **весь запуск** | **4 мин 31 с** |

Вес файла — 9 680 027 байт против 9 598 111 у прежнего `I-01_...v2.mp4`.
Кодирование то же самое.

Репозиторий публичный, поэтому минуты Actions бесплатны и не считаются.

```
воркфлоу «Рендер ролика» → align.py → settime.py → Remotion → ffmpeg → MP4
```

**Сцены под Remotion не переписывались и переписываться не будут.** Сцена как
была чистой функцией `window.seek(t)`, так и осталась; Remotion открывает тот
же самый `i01.html` в iframe и дёргает `seek` на каждом кадре. Обёртка —
`remotion/src/HtmlScene.tsx`, тридцать строк. Проверено покадрово: картинка
совпадает с локальным рендером кадр в кадр.

**Кодирует не Remotion, а наш ffmpeg.** Свой кодировщик Remotion не даёт
задать `deblock` и `aq-mode`, а без них зерно съедается и на градиенте
возвращаются полосы. Замерено на кадре 140 И-01, PSNR против эталонного PNG:

| | PSNR | вес кадра |
|---|---|---|
| Remotion своим кодировщиком, `--crf=16` | 43,2 дБ | 3,1 КБ |
| Remotion кадрами + наш ffmpeg | 44,6 дБ | 8,5 КБ |

Поэтому воркфлоу по умолчанию просит у Remotion PNG-последовательность
(`--sequence`) и собирает её строкой из этого раздела. Галочка «черновик»
отдаёт кодирование Remotion — быстрее, для проверки годится, для выкладки
нет.

**Грабли Remotion:**

- Remotion запускает браузер в старом headless-режиме, которого в обычном
  Chrome больше нет. Нужен `chrome-headless-shell`: в облаке его ставит
  `npx remotion browser ensure`, в контейнере он уже лежит —
  `/opt/pw-browsers/chromium_headless_shell-*/chrome-linux/headless_shell`,
  передавать через `--browser-executable`.
- Событие `load` у iframe срабатывает и на пустом `about:blank`, который
  показывается до настоящего документа. Ждать надо появления `window.seek`
  и загрузки шрифтов, опросом; иначе `delayRender` виснет и рендер падает
  по таймауту.
- Remotion нумерует кадры по их количеству: `element-000.png` на 150 кадрах
  и `element-0000.png` на 1374. Жёсткий `%03d` в ffmpeg сломается, брать
  маской `-pattern_type glob`.
- `npx create-video@latest` задаёт вопросы и через пайп не проходит. Проект
  собран руками, он уже в репозитории — заново создавать нечего.
- `ffprobe` в облаке нет: `imageio-ffmpeg` кладёт только `ffmpeg`. Длину и
  потоки печатать его же разбором.
- Выгрузку артефакта ставить с `if: always()`. Первый запуск отрендерил всё
  за четыре минуты и потерял результат из-за упавшей строчки диагностики.
- Воркфлоу запускается сам только на правки `remotion/**` и самого файла
  воркфлоу. Правки сцен его не будят намеренно: их бывает много подряд.
- GitHub предупреждает, что `actions/checkout@v4`, `setup-node@v4` и
  `upload-artifact@v4` целятся в Node 20, который объявлен устаревшим.
  Пока это только предупреждение, запуск идёт на Node 24. Дойдут руки —
  поднять до `@v5`.

**Лицензия.** Remotion бесплатен для физических лиц, некоммерческих
организаций и компаний до трёх сотрудников. Канал под это подходит. Если
появится юрлицо больше — нужна платная лицензия, `remotion.pro/license`.

**Старое наследство Remotion удалено 16.09.2026** — те файлы были от первого
подхода, где ролик писался на React напрямую. Лежат в истории git до коммита
`3d91baa`.

## 2. Обязательное условие сцены

Всё состояние — **чистая функция одного `t`** (секунды). Экспортируется как `window.seek(t)` и `window.META = {FPS, DUR, FRAMES}`. Никаких CSS-анимаций и переходов: при покадровом захвате они недетерминированы и дают дрожание.

**Второе условие, введено 16.09.2026: время живёт в объекте `T` наверху файла.**

```js
const T = { src:"голос.mp3", DUR:47.88, B:[[0.32,4.11],[4.55,6.40], …] };
```

`B` — границы блоков дорожки, ровно то, что выдаёт `align.py`. Абсолютных
секунд в коде сцены нет: события считаются от блоков.

```js
bs(i), be(i)        начало и конец блока i (нумерация с единицы)
at(i,p)             доля p внутри блока i
enter(i,d)          вход акта за d секунд до блока, но не раньше,
                    чем договорён предыдущий блок
gone(i,next)        уход акта: держим всю паузу, убираем к приходу
                    следующего акта
```

Подставляет тайминг `settime.py`, руками объект не править.

**Блоков меньше, чем актов — это нормально.** В И-02 блок 8 «Чтобы заработать
столько же… Три клиента вместо одного» держит сразу два акта: столбики и
человечков. Граница ставится долей — `at(8,0.56)`, ровно на «Три клиента», —
и уход первого акта считается от неё, а не от конца блока. Дробить текст
озвучки под картинку нельзя: паузы диктора важнее.

**Экран передаётся в один момент, а не двумя независимыми фейдами.**
`swap(i)` — середина паузы после блока i. Уходящий акт гаснет ровно к ней,
приходящий с неё начинается, длительность фейда общая и короткая — 0,22 с.

Это третья редакция правила, и две первые были неверны:

1. «Вход за 0,4 с до блока, уход через 0,3 с после». На паузе короче 0,4 с
   акты встречались на экране, на паузе длиннее секунды картинка уходила
   раньше времени и титр висел над пустым экраном.
2. «Вход не раньше конца предыдущего блока, уход не позже прихода
   следующего акта». Выглядело верно и прошло проверку на синтетике — но
   на живой дорожке И-01 пауза между обещанием и разрывом оказалась 0,39 с,
   а фейды по 0,32 с каждый. Два фейда по 0,32 в паузу 0,39 не помещаются
   ни при каком раскладе: `max` выбирал конец блока для ухода и его же для
   прихода, и акты накладывались на треть секунды. Это увидел пользователь
   на готовом ролике.

Вывод, который стоило сделать сразу: **длительность фейда не может быть
константой, если пауза бывает короче двух фейдов.** Либо фейд короткий и
общий, либо считается от ширины паузы.

**Наложения проверяются машинно.** `overlap.py` прогоняет сцену покадрово и
печатает все отрезки, где на экране больше одного крупного блока. Гонять
после любой правки таймингов — глазами такие вещи видно только на готовом
ролике, то есть на четыре минуты рендера позже.

**Сцену можно строить до записи дорожки.** `settime.py --estimate` кладёт
оценку по темпу Станислава, сцена рендерится и проверяется. Когда придёт
mp3, оценка заменяется настоящей раскладкой одной командой — переписывать
сцену не нужно.

## 4. Структура ролика-инфографики

Порядок жёсткий. Ролик, начинающийся сразу с числа, не работает: зритель листает не от пустого экрана, а от непонимания, о чём это.

```
постановка   узнаваемая ситуация во втором лице, НОЛЬ цифр
обещание     начинается словом «считаем» + четыре статьи расчёта
разрыв       число, буквально противоречащее постановке
расчёт       карточка заполняется построчно
главное число
белая вспышка — смена акта, ровно одна на ролик
второй акт
CTA, картинка возвращается к началу (петля)
```

Доли даны без секунд намеренно: границы берутся из дорожки. Готовые постановки и обещания для всех 15 — в `PACK-01-otkrytiya.md`.

## 5. Вёрстка вертикали

**Безопасные поля** (соглашение проекта, не опубликованный стандарт площадок): верх 0–240, низ 1400–1920, правый край 880–1080. Рабочее поле `x 60…820 · y 240…1400`. Оптический центр — **y 780**, не 960.

**Сетка.** Титр y 258–458. Карточка y 516–1230. Крупное число y 640–1000. Пилюли выбора — под карточкой, y ~1128. Футер y 1318 и 1356.

**Бюджет чтения.** Зритель успевает около **2,5 слов в секунду**. Сколько
блок держится на экране — столько на нём и может быть слов, считая заголовок,
подписи и мелкий текст. Не влезает — надпись **убирается**, а не уменьшается
кеглем: мелкий текст не читается быстрее, он читается хуже.

Проверено на И-01 16.09.2026. Дорожка Станислава вышла 42,5 с вместо
ожидавшихся 48, а картинка была нарисована под 46-секундный ролик — и в
четырёх местах зритель перестал успевать:

| момент | держится | было слов | бюджет | что сняли |
|---|---|---|---|---|
| обещание | 2,1 с | 14 | 5 | подпись «до последнего рубля» |
| рабочее место | 0,9 с | 9 | 2 | разбивку аренда · техника · софт |
| вспышка | 1,1 с | 11 | 3 | вторую строку под крупной |
| льготный тариф | 2,3 с | 15 | 6 | три условия списком |

Списки читаются быстрее прозы — их сканируют, поэтому четыре статьи расчёта
в обещании остались, но появляются теперь разом, а не по очереди: выкладывать
их с задержкой 0,2 с значило съесть треть блока на анимацию.

Снятое не пропадает: разбивка рабочего места и три условия МСП уходят в пост
Телеграма, где их можно рассмотреть.

**Грабли, на которые уже наступили:**

- Числа вида «134 000 ₽» при кегле выше ~130 не влезают в колонку 760 px и переносят знак рубля на вторую строку. Ставить `whiteSpace: nowrap`.
- Титр обязан укладываться в две строки. Кегль подбирается функцией `fitCaption` от 76 px вниз с шагом 2, результат кешируется по тексту. Без этого титр наезжает на карточку.
- Строки карточки ниже 122 px наезжают друг на друга.
- Межстрочные интервалы всех строк карточки должны быть равны, иначе разнобой виден.
- Крупный итог поверх карточки требует затемняющей подложки `rgba(10,13,12,.93)`, иначе цифры карточки просвечивают.
- **Пилюли выбора нельзя ставить над карточкой** — они бьют по титру. Место под карточкой, y ~1128.
- Столбики и любой нижний блок держать выше y 1300, иначе накрывают строку расчёта в футере.
- Эхо-строка петли на CTA не должна накладываться на текст CTA.
- Служебные подписи — в одном регистре. Капс.
- **ЛАНСКОЙ пишется с заглавной.** Это фамилия персонажа.

**Полосы на градиенте.** В 8-битном H.264 плавный градиент даёт видимые ступени. Лечится зерном: тайловый PNG-шум 180×180 (нормальное распределение, σ≈26) как data-URI, `opacity .055`, `mix-blend-mode: overlay` поверх фона. Плюс более пологий градиент и `crf 16` с `deblock=-1,-1:aq-mode=3`.

## 6. Визуальный язык

### Оформление — структура HeroUI, цвета свои

Источник токенов — `design-tokens.json` в корне, разносит их по сценам
`tokens.py`. В сценах токены **вписаны, а не подключены**: сцена обязана
оставаться одним самодостаточным файлом, её открывает iframe при рендере.
Руками в сцене не править — следующий запуск `tokens.py` перезапишет.

Из HeroUI (`@heroui/theme`, тёмная тема) взято четыре вещи:

| | HeroUI | у нас |
|---|---|---|
| Лесенка поверхностей | content1…content4 от чёрного | те же шаги в нашем тоне: `#18201E` `#242D2B` `#38433F` `#4A5551` |
| Разделитель | `rgba(255,255,255,.15)` | так же — одна линия работает на любой поверхности |
| Скругления | 8 · 12 · 14 px на макете 390 | ×2,8 под сцену 1080: `sm 22` `md 34` `lg 40` `full` |
| Движение | приход 250 мс ease-out, уход 60 мс ease-in | приход 0,25 с, уход 0,14 с |

**Цвета не менялись.** Зелёный, красный и бирюзовый несут смысл по этому же
разделу и уже узнаются в ленте; палитра HeroUI (success `#17c964`, danger
`#f31260`, primary `#006FEE`) их бы переписала, а фон `#000000` убил бы
зелёное свечение. Решение пользователя от 17.09.2026: берём структуру,
цвета оставляем.

**Асимметрия движения — главное, что стоило перенять.** Акт приходит плавно
и уходит вдвое быстрее. Это не только красивее: короткий уход освобождает
место в узких паузах между блоками, из-за которых акты налезали друг на
друга.

**Наша палитра и так лежит на координатах HeroUI v3.** Проверено переводом
в oklch — ту систему, в которой HeroUI задаёт цвета:

| | наш | HeroUI v3 |
|---|---|---|
| фон | `oklch(15,5% 0,005 173)` | `oklch(14,5% 0 0)` |
| деньги · success | `oklch(77,0% 0,164 160)` | `oklch(76,5% 0,177 163)` |
| потеря · danger | `oklch(65,4% 0,195 25,9)` | `oklch(63,7% 0,237 25,3)` |

Светлота совпадает в пределах двух пунктов, тон красного — в пределах
градуса. То есть канал не отклоняется от системы, а сидит на её тоне чуть
менее насыщенно и с зеленоватым фоном вместо нейтрального. Решение
оставить свои цвета оказалось не компромиссом, а совпадением.

Бирюзовый `#3FB7C9` — единственное настоящее расхождение: у HeroUI на этом
месте синий `accent`. Но accent у них — цвет фокуса в интерфейсе, а у нас
цвет бренда, роли разные.

**Шкала скруглений у второй и третьей версии разная.** Вторая: 8 · 12 · 14,
третья: 6 · 8 · 12. Под сцену 1080 это 22 · 34 · 40 против 17 · 22 · 34.

туда раньше, чем выяснилось, что установлена третья. Разница в шесть
пикселей на карточке шириной 760 глазом не ловится, поэтому пересобирать
ролики только ради неё не стоит; поправить при следующей общей переделке.

**Навыки HeroUI.** `npx skills add heroui-inc/heroui` ставит три навыка в

### Прежние правила

- Тёмный фон `#0A0D0C` с зелёным радиальным свечением.
- **Зелёный `#2FD38E` — деньги, красный `#F0524D` — потеря, бирюзовый `#3FB7C9` — бренд.** Других значений у цвета нет.

## 7. Звуковые эффекты

**Сцена сама объявляет, когда что звучит.** В `window.SFX` лежит список
`{t, s}` — время и имя эффекта, посчитанные от тех же якорей, что двигают
картинку. Поэтому звук не может разъехаться с изображением: подгонять на
слух нечего.

**Кадры при этом не трогаются.** `mixsfx.py` читает `window.SFX` из сцены и
подмешивает эффекты в готовый MP4, копируя видеодорожку как есть. Менять
звук можно сколько угодно — рендер не нужен, сведение занимает секунды.

```bash
python3 sfx.py                                       # синтезировать набор
python3 mixsfx.py i01 out/I-01.mp4 out/I-01_sfx.mp4  # подмешать
```

**Синтезированные звуки не подошли.** `sfx.py` собирал их из шума и тонов на
numpy — расчёт был на то, что длительность подгоняется под анимацию до
миллисекунды и лицензии не нужны. Пользователь послушал 17.09.2026: звучат
плохо. Скрипт оставлен как запасной, но по умолчанию берём готовый пак.

Урок общий: **Claude не слышит аудио, поэтому любой звук — это догадка до
тех пор, пока его не послушал человек.** Не разносить звук по всем роликам,
пока хотя бы один не подтверждён на слух.

**Звуки берём из `assets/sfx/`** — 34 файла, справочник с замерами в
`assets/sfx/SFX.md`. Соответствие «реплика сцены → файл» в `sfx-map.json`,
замеры машиной — в `sfx-index.json` (считает `sfxindex.py`).

Две вещи делают звук попадающим, а не просто присутствующим.

**Первая: по какому месту файла равнять — зависит от звука.** У реплики в
сцене есть режим `m`.

`m:'peak'` (по умолчанию) — на событие ставится пик. Годится удару с
хвостом: положишь такой началом на кадр, и он прозвучит позже события.

`m:'onset'` — на событие ставится **первое слышимое место**. Обязательно для
звуков-серий. У `counter.mp3` девять щелчков идут с 0,10 по 0,71 с, а пик
сидит в хвосте на 0,74. Выровняли по пику — вся серия отыграла ДО того, как
число тронулось: щелчки кончились на 17,53, а число пошло на 17,56. Мимо
целиком, и это сразу услышал пользователь. По `onset` восемь щелчков из
девяти ложатся внутрь окна набегания.

Правило: **звук-серия равняется по началу, удар — по пику.** Длина серии
при этом должна совпадать с длиной анимации: у нас счётчик крутится 0,55 с,
щелчки занимают 0,61 с — сходится.

**Вторая: уровень зависит от того, звучит эффект под речью или в паузе.**
Голос Станислава идёт около −16 dB RMS.

| Где | Уровень |
|---|---|
| Под речью | −16 dB |
| В паузе между блоками | −10 dB |
| Акцент на главном числе | −5 dB |
| Ярким (выше 3 кГц) | ещё −3 dB: бьют в полосу разборчивости согласных |

Роль определяется сама: сцена выставляет наружу `window.T`, и по границам
блоков видно, попал эффект в речь или в паузу. Реплика с `{a:true}` —
акцент.

Это на 6 дБ выше, чем советует `assets/sfx/SFX.md`: по первой пробе
эффекты оказались слишком тихими. Рекомендации справочника считались от
разборчивости речи, но на слух вышло, что их не слышно вовсе. Общую добавку
можно дать ключом `--gain`, не трогая код. Клиппинга нет: пик ролика
поднялся с −0,6 до −0,5 дБ.

**Плотность.** В референсном ролике (Пронин, 44 с) насчитано около семи
явных эффектов в минуту. Первая версия И-01 имела девятнадцать — втрое
гуще. Норма: отмечать событие, а не сопровождать каждое движение.

| Эффект | Длина | Где |
|---|---|---|
| `count` | 550 мс | число набегает: щелчки с подъёмом тона |
| `land` | 550 мс | приход крупного числа: низкий удар с обертоном |
| `flash` | 420 мс | смена акта: подъём шумом, срезанный на вспышке |
| `row` | 100 мс | строка карточки встала на место |
| `pill` | 140 мс | клик по пилюле выбора, CTA |
| `blip` | 120 мс | короткая отбивка |

**Эффекты идут на −17 дБ под голосом** и не меняют громкость ролика:
средняя и пиковая на И-01 совпали до децибела с версией без них. Это
намеренно — их должно быть слышно на грани, ощущаться, а не слушаться.
Громкий интерфейсный звук в ролике про деньги выглядит дёшево.

**Claude не слышит аудио.** Расставить эффекты по кадрам и свести — может,
судить о звучании — нет. Слушать и решать всегда пользователю.

## 9. Выравнивание текста по дорожке — `align.py`

Не распознавание речи. Текст известен заранее, задача — найти, где какое слово прозвучало.

```bash
python3 align.py voice.mp3 text.txt timing.json
```

Нужны только **numpy и ffmpeg**, оба уже стоят. Ставить нечего.

**Как устроено.** Дорожка → огибающая энергии 100 кадров/с → вероятность «здесь речь» (логистика от порога `floor + 0.42·(peak−floor)`, наклон `span/9` дБ). Текст → цепочка единиц «слово · пауза»: длительность слова = число слогов × темп, длительность паузы = приор по знаку препинания (`,` 0,10 с · `—` 0,12 · `:` 0,18 · `.` 0,28 · `…` 0,45 · пустая строка 0,55). Сшивка — динамическое программирование с явной длительностью, штрафы `K_WORD=9` (квадрат логарифма отношения) и `K_GAP=4`.

**На выходе** JSON: длина дорожки, цена, границы каждого блока и время начала-конца **каждого слова**.

**Две метрики самопроверки, обе печатаются:**

| | Норма | Что значит отклонение |
|---|---|---|
| Цена | 0,10–0,15 | от 0,25 — начитан не тот текст или брак в записи |
| Тишина на границах блоков | >70% и пауза >0,15 с | иначе печатается «ВНИМАНИЕ», раскладку сверять на слух |

**Проверено на реальных дорожках:** Станислав 47,88 с, цена 0,135; Марио 50,70 с, цена 0,131. Границы блоков — **10 из 10** попали в настоящие паузы у обоих.

Контрольная точка: в дорожке Станислава после «Вы наняли человека» пауза 1,25–1,59 с. Алайнер ставит конец слова «человека» на 1,26, начало «Договорились» на 1,59.

**Таблицу показывать пользователю до рендера.** Всегда.

После подтверждения таблицы раскладка уходит в сцену:

```bash
python3 settime.py i01.html timing.json
```

`sync.py` — предыдущий инструмент, резал по паузам. Давал 8 блоков из 10 (пауза между предложениями и пауза между абзацами по уровню сигнала неразличимы). Оставлен в репозитории как запасной, по умолчанию не используется.

## 12. Заливка в репозиторий через браузер

Рабочий порядок, проверен трижды:

1. `list_connected_browsers` → `select_browser` по deviceId (браузер пользователя — **Brave**).
2. Открыть `https://github.com/MrTailsGH/lanskoy-motion/upload/main`.
3. `find` «file input element for choosing files» → `file_upload` со списком путей из `/mnt/user-data/outputs/…`. **До 10 МБ за вызов.**
4. Кликнуть по полю сообщения коммита, напечатать текст.
5. Кнопка «Commit changes» кликается **по координате**, может не сработать с первого раза — проверять скриншотом.
6. Сверить результат клоном и контрольными суммами.

**Грабли:**

- `navigate` без явного `tabId` иногда рапортует успех, а вкладка остаётся на `chrome://newtab`. Навигировать с `tabId` или создать новую вкладку.
- `deviceId` браузера меняется при переподключении. Старый не переиспользовать.
- Если `file_upload` упал с «extension disconnected mid-operation», файл всё равно мог прикрепиться. Проверить список и удалить дубликат: кнопка «Remove <имя файла>» ищется через `find`, клик по ref.
- После клика по крестику страница может внезапно оказаться сильно зазумленной, и `Page.captureScreenshot` отваливается по таймауту. Работать через `find` и клики по ref вместо координат.
- `file_upload` принимает пути контейнера `/mnt/user-data/outputs/…`. Пути подключённой папки `C:\…` — **не принимает**.
- Кириллицу из имён файлов убирать: веб-загрузка GitHub её иногда ломает.

контейнере. Подробности — `pult/README.md`.

Два решения, за которые стоит держаться:

**Браузер не выполняет команды.** Он присылает имя задачи из словаря `ZADACHI`
и параметры, которые сервер проверяет: ролик — из перечня, число — от одного
до двадцати, ссылка — строго на YouTube. Сервер слушает только `127.0.0.1`.
Новая задача добавляется в `ZADACHI`, а не в разметку страницы.

**Кнопка гаснет, если инструмента нет.** Сборка требует bash, node и ffmpeg —
на домашней машине их нет, и кнопка гаснет сразу, вместо падения на полпути.
Так одна и та же страница честно работает и дома, и в контейнере.

Зависимостей нет — только стандартная библиотека. Это сознательно: пульт
должен запускаться на машине, где ничего не настроено.

### Раннер: четыре грабли на четырёх запусках

Первый живой прогон «Снимка» прошёл через четыре падения подряд, все —
особенности Windows, ни одной ошибки в логике. Записано в шапке
`.github/workflows/snimok.yml`, здесь коротко:

1. **`bash` не найден.** Git для Windows кладёт `bash.exe` в `Program
   Files\Git\bin`, а в PATH добавляет только `cmd`. Воркфлоу переписан на
   PowerShell целиком.
2. **`running scripts is disabled`.** По умолчанию стоит ExecutionPolicy
   Restricted, а раннер передаёт каждый шаг временным `.ps1`. Лечится в
   воркфлоу — `shell: powershell -NoProfile -ExecutionPolicy Bypass -File {0}`,
   политику машины не трогаем.
3. **`Missing closing '}'`.** Раннер пишет временный файл в UTF-8 без BOM,
   PowerShell 5.1 читает его как ANSI. Кириллица внутри `run:` превращается в
   кракозябры и ломает разбор — падение приходит не там, где ошибка. Внутри
   `run:` только латиница, объяснения в комментариях YAML.
4. **`UnicodeEncodeError: '→'`.** Консоль отдаёт cp1251, и стрелка «→» из
   `svodka.py` роняет Python уже после всей работы. В воркфлоу добавлены
   `PYTHONUTF8` и `PYTHONIOENCODING`, а `snimok.py`, `razbor.py`, `svodka.py`
   и `radar.py` переключают свой вывод на UTF-8 сами — они запускаются и
   руками тоже.

Общее правило: **на Windows кодировка ломает не там, где ошибка.** Падение на
печати результата выглядит как падение расчёта.

### YouTube рвёт рукопожатие с домашнего адреса

прокси в секрет `SNIMOK_PROXY`.

различается «всё из верхушки уже разобрано» (тишина, код ноль) и «были
попытки, все провалились» (отказ). **Инструмент, который умеет вернуть
пусто, обязан отличать «нечего делать» от «не вышло».** Та же ошибка уже была

### ВПН в браузере пульту не помогает — 20.09.2026

Егор запустил пульт в браузере с включённым ВПН и спросил, можно ли теперь
снимать ролики. Нельзя, и это стоит держать в голове про всю затею с пультом:

маршруты процесс берёт при старте.

**Разобрать готовый файл.** Появился ключ `snimok.py --fayl ПУТЬ` и кнопка

ложатся в `Primeri/<имя файла>/`, сводка пересобирается сама, видео в
репозиторий не едет.

Плюс поле прокси на карточках снимка и разбора — если ВПН показывает
локальный порт. Адрес проверяется на сервере и запоминается в браузере.


### Обновление пульта — 20.09.2026

Папка на домашней машине обновляется сама: `PULT.bat` и `pult.sh` делают
`git pull --ff-only` перед запуском. Три решения в этой мелочи, и все три
стоит держать:

**`--ff-only`, а не просто `pull`.** Если на машине правили файлы руками,
обновление откажется вместо слияния с конфликтами за спиной. Молчаливое
слияние на чужой машине — это потерянная работа, которую никто не заметит.

**Неудачное обновление не мешает запуску.** Пульт поднимается на том, что
есть, и пишет об этом. Инструмент, который отказывается работать из-за
неудавшегося обновления, хуже устаревшего.

**Страница сама говорит, что устарела.** Сервер читает `pult.py` при старте,
поэтому после обновления продолжает работать по старому коду. Он сравнивает
время файлов с тем, что было при запуске, и выводит полосу «Пульт обновился,
но работает по старому коду». Заодно раз в две минуты спрашивает GitHub про
последний коммит и показывает «на GitHub есть свежее» с кнопкой рядом.

Общее: **инструмент обязан знать, что он устарел, и сказать об этом сам.**


### Графика в пульте — 20.09.2026

В пульт добавлены три вещи, которых не было нигде: лента времени чужого
ролика, лента блоков нашего и полосы выбросов радара. Ленты рисуются **на
общей шкале секунд** — иначе сравнивать ритм бессмысленно.

Что видно сразу, и ради чего это делалось: у чужих роликов за 70–80 секунд
**три склейки и три перехода**, а движение в кадре идёт почти непрерывно.
У нас за 50 секунд **шестнадцать блоков дорожки**. Прямо это не сравнивается
— блок речи не равен склейке, паузы у нас короткие, — но вопрос «не слишком
ли часто мы переключаем картинку» теперь задаётся на числах, а не на
ощущении. Следующий шаг: вынести на ленту наши настоящие переходы сцены
(границы актов), тогда сравнение станет прямым.

**Цвета марок проверены, а не подобраны на глаз.** Прогнали через
`validate_palette.js` из навыка dataviz: брендовые `#2FD38E` и `#3FB7C9` не
прошли по светлоте на тёмной карточке, а затемнённый бирюзовый проваливал
порог насыщенности. Рабочая пара — `#EE5A52` и `#17A2BC`: проходят все пять
проверок, включая разделимость при дальтонизме (ΔE 16,6). Это те же тона
канала, просто другие шаги. Зелёный блок нашего ролика — `#23A874`.

Правила, которые соблюдены и которые легко нарушить в следующий раз:
**одна шкала** (двух осей в одном графике не бывает), **полосы выбросов
одного тона** — ролики это не шкала величин, длина полосы уже кодирует
число; **высота столбика движения — корень**, а не линейная шкала: пики на
склейках в двести раз выше обычного шевеления и задавили бы всё остальное.


### Приёмка своих роликов — 20.09.2026

`priemka.py` меряет наши готовые ролики тем же `razbor.py`, что и чужие, и
сверяет с нормой. **Норма считается из `Primeri/`, а не задаётся руками:**
растёт набор разборов — уточняется норма. Исключение одно — громкость: её
задаёт площадка, −14 LUFS, и все три разобранных чужих ролика стоят на
−14,3 неслучайно. Отчёт ложится в `priemka/PRIEMKA.md`, в репозиторий едет
только он: кадры и замеры пересчитываются за минуту.

Судится готовый ролик — сведённый со звуком, если он есть. Иначе половина
расхождений в отчёте была бы про файл, который никто не публикует.

**Что нашлось первым же прогоном.** Новая дорожка И-01 из Eleven Labs
пришла на −22,7 LUFS, тогда как прежние дорожки приходили на −14,8. Разброс
между выгрузками — восемь децибел, и заметить это на слух в наушниках
нельзя. YouTube приглушает громкое, но **тихое не поднимает**: ролик просто
звучал бы глуше соседних в ленте.

Отсюда правило и правка в `mixsfx.py`: **громкость больше не зависит от
того, что отдал синтез.** Сведение идёт в два прохода — звук собирается в
WAV, меряется, и только потом ставится точная добавка. Один проход
`loudnorm` подгоняет динамику на ходу и промахивается; здесь промах виден в
ленте. И-01 после правки: −22,2 → −14,7 LUFS, лимитер съедает три десятых,
это в допуске.

**Что расходится у всех пяти роликов и чем это лечить.** Доля покоя
87–90% против 73–82% у чужих, средняя длительность движения 0,10–0,14 с
против 0,24–0,28. То есть наша картинка стоит дольше, а когда двигается —
дёргается короткими рывками. Чужие двигают меньше сущностей, но дольше и
плавнее. Это следующая работа по визуальному языку, не по коду.

Шестой запуск прошёл целиком: раннер скачал ролик, замерил, закоммитил и

инфографика про деньги. Разбирать полезно что угодно — мерить себя можно
только по сопоставимому. И проверять это надо при каждом пополнении: один
чужой жанр незаметно обнуляет все пороги.


### Наработанное на машине само никуда не едет — 20.09.2026

Егор спросил: если пульт всё делает на компьютере, как GitHub узнаёт о
сделанном и не сотрёт ли следующий запуск. Опасение наполовину верное, и
дыра была настоящая.

**Стереть не сотрёт.** Обновление идёт через `git pull --ff-only`: при
расхождении он останавливается и ничего не трогает. Папка раннера —
отдельная копия, её GitHub действительно чистит перед каждым запуском
(`git clean -ffdx`), но к папке пульта это отношения не имеет.

**А вот не доехать может.** Сами отправляются только разборы чужих роликов
(`snimok.py --push`). Радар, приёмка, тайминги и правки сцен оставались на
машине молча. Копится — и в какой-то день обновление перестаёт работать,
потому что те же файлы изменились и там, и тут.

Появился `otpravit.py` и кнопка «Отправить» в полосе версии, рядом со
счётчиком «не отправлено: N». Она собирает всё разом, подписывает коммит
по-человечески («Пульт: радар, приёмка, тайминги»), забирает чужое
`--rebase` (раннер коммитит в ту же ветку) и отправляет.

Правило: **у всего, что инструмент делает локально, должен быть видимый
счётчик неотправленного и кнопка рядом.** Иначе работа копится в тишине,
а ломается всё сразу и не там, где причина.
